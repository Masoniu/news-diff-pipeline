# News Diff Pipeline

Порівняльний аналіз новинних статей: пошук усіх джерел, що писали про
ту саму подію, і виявлення фактологічних та наративних розбіжностей
між ними.

## Принцип розробки

Пайплайн будується **по кроках**, кожен крок:
- незалежний модуль з чітким входом/виходом,
- має власний CLI-раннер у `scripts/`,
- зберігає результат у `data/<stage>/*.json` — щоб можна було відкрити
  файл руками й перевірити, чи все ок, ПЕРЕД тим як переходити далі,
- має тести в `tests/`, які можна запустити окремо.

Це навмисно, щоб коли щось зламається — було зрозуміло, на якому саме
кроці, а не "десь усередині чорної скриньки".

## Статус

- [x] **M1 — Ingestion**: парсинг статті (newspaper4k → trafilatura fallback) + ключові слова (KeyBERT)
- [ ] M2 — Пошук кандидатів (GDELT DOC 2.0 → SearXNG → ddgs fallback)
- [ ] M3 — Event coreference фільтр (локальна Ollama)
- [ ] M4 — Sentence split + SBERT + many-to-many вирівнювання
- [ ] M5 — NER-bypass (факти) + NLI (семантика) розмітка пар
- [ ] M6 — LLM-пояснення дельти + запис у PostgreSQL/Neo4j

## Встановлення

```bash
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Перший запуск `extract_keywords()` завантажить мультимовну
Sentence-BERT модель (~470 МБ) з HuggingFace Hub — потрібна мережа,
далі працює офлайн з кешу.

## Крок 1 (M1): Ingestion

### Запуск на реальній статті

```bash
python scripts/run_stage1.py --url "https://example.com/якась-новина"
```

### Запуск офлайн (на тестовій фікстурі, без мережі)

```bash
python scripts/run_stage1.py --html-file tests/fixtures/sample_article.html \
    --url "https://example-news.ua/lviv-crash"
```

### Як перевірити, що крок відпрацював правильно

1. Відкрий файл, що з'явився в `data/stage1/<timestamp>-....json`.
2. Перевір вручну:
   - `article.title` — заголовок відповідає статті?
   - `article.text` — текст повний, без обрізків, без сміття (меню, реклама)?
   - `article.publish_date` — дата коректна (не `null`, якщо на сторінці вона є)?
   - `article.extraction_method` — `"newspaper4k"` чи `"trafilatura"` (для діагностики, який екстрактор спрацював)
   - `keywords` — чи адекватні ключові слова стосовно суті новини?
3. Якщо `article.text` порожній або сміттєвий — це майже завжди означає,
   що сайт віддає контент через JS (потрібен headless-браузер, наприклад
   Playwright — не входить в MVP) або блокує скрапери по User-Agent.

### Тести

```bash
pytest tests/test_stage1.py -v
```

Тести парсера повністю офлайн (працюють на фікстурі
`tests/fixtures/sample_article.html`). Тест ключових слів мокає саму
модель — перевіряє тільки "проводку" (вхід → вихід у правильному
форматі), не якість екстракції. Якість керуй руками через
`run_stage1.py` на реальних статтях.

## Наступний крок

M2 — пошук статей-кандидатів про ту саму подію через:
1. GDELT DOC 2.0 API (безкоштовний, без ключа, спеціально під цю задачу)
2. SearXNG (self-hosted, якщо GDELT не покрив локальні джерела)
3. `ddgs` (DuckDuckGo-скрапінг, останній рубіж)

Буде реалізовано в наступній ітерації.
